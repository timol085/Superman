Superman

Combine every runner's fastest leg into one ideal race — then see how far each runner falls behind it, per stage or across the whole competition.

Dark mode
Auto-loading needs a local server. This page was opened directly from disk, so the browser won't let it read the data/stageN.json files. In a terminal, run this once inside the project folder:

cd "this folder" && python3 -m http.server 8000

then open http://localhost:8000. Or just double-click serve.command in the folder.

Data comes from data/stage1.json … data/stage5.json — edit those files, then click Reload data files. Superman values shown in grey italic were auto-filled from the fastest runner (no Superman value given for that leg).

JSON file format (e.g. data/stage1.json) 
{
  "controls": 3,                        // optional — inferred from the arrays if omitted
  "superman": ["2.27", "3.01", "5.45"], // optional — omit to auto-use the fastest runner
  "runners": {
    "Ulrik Olsson":   ["2.37", "3.01", "5.58"],
    "Håkan Svensson": ["2.50", "3.05", "5.45"],
    "Anders Svensk":  ["2.27", "3.30", "5.58"],
    "Michael Wehlin": ["2.41", "3.12", "5.50"],

    "Guest Runner":   ["2.44", "3.20", "6.02"]  // extra — this stage only
  }
}

// Times are strings in m.ss (or m:ss). Use "3.10" not 3.1 so the
// trailing zero is kept. A blank "" means a missed control.
// Names are matched loosely (first name is enough); or use a plain
// array of split-lists in the order shown above.
//
// Any runner beyond the core four (like "Guest Runner" above) shows
// only in this stage's graph & table — never in the Combined summary.

Row 1 is each runner's total time for that stage; row 2 is the cumulative time through that stage, so the value under Etapp 5 is the overall competition time. Runners are ordered fastest first. Only the core four appear here — stage-only guests are excluded.
